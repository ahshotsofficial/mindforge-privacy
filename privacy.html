Privacy Policy

Effective date: November 15, 2026 · Applies to the Mindforge automation and this website.

1. Overview

Mindforge is a personal, self-hosted automation that creates one psychology explainer video per day and uploads it to the owner's own YouTube channel as a private video. This policy explains what data the system processes, which permissions it uses, where data is stored, and how it is retained and deleted.

Mindforge is operated by a single individual (the "owner", "we", "us") for their own YouTube channel. It has no other users, collects no audience data, and never publishes content publicly without an explicit manual action by the owner.

2. Summary (plain language)

  • The system connects to Google using OAuth 2.0 with exactly one permission: youtube.upload.
  • It uploads videos only — always marked private. It cannot delete, edit or publish videos, cannot change their visibility, and cannot read your watch history, comments, playlists or channel analytics.
  • Access credentials (an OAuth refresh token) are stored exclusively in GitHub Actions Secrets, encrypted at rest by GitHub.
  • This website sets no cookies, uses no analytics or tracking, and collects no personal data from visitors.

3. Google OAuth 2.0 and what we access

To upload videos unattended, the daily automation authorizes once (by the owner, interactively) and receives a long-lived refresh token. At every subsequent run, that refresh token is exchanged for a short-lived access token, which is used to call the official YouTube Data API v3.

3.1 The requested permission

The application requests exactly one OAuth scope:

ScopeWhat it allowsWhat it does NOT allow
https://www.googleapis.com/auth/youtube.upload Uploading videos to the authorized account and setting their metadata (title, description, tags, category, privacy status) at upload time. Editing or deleting existing videos; changing visibility later; reading watch history, comments, likes, subscriptions, playlists or analytics; managing the channel.

The consent screen may display the permission under the name "Manage your YouTube videos". For this automation it is used exclusively to upload new videos marked private.

3.2 How the token is used at runtime

During a daily run, the refresh token is exchanged for an access token in memory. Access tokens are short-lived (typically one hour) and are never written to disk, logged, or included in any repository file.

4. YouTube Data API usage

The automation calls exactly two API methods:

MethodPurpose
videos.insert Uploads the rendered MP4 (resumable, chunked upload) with metadata taken from the generated content package. The upload body sets privacyStatus: "private".
Upload response The upload response itself is used to confirm the video was created as private. No additional read scopes are requested.

Video visibility: every uploaded video is created with privacyStatus: "private". The automation has no code path to make a video public or unlisted, and none of the permissions it holds would allow it to change visibility afterwards. Publishing a video is always a manual action performed by the owner in YouTube Studio.

Metadata: titles, descriptions, tags and the video category are generated automatically from the content package. They do not contain personal data.

5. GitHub Actions Secrets (credential storage)

OAuth credentials are stored as three GitHub Actions repository secrets:

  • YOUTUBE_CLIENT_ID — the public OAuth client identifier,
  • YOUTUBE_CLIENT_SECRET — the OAuth client secret,
  • YOUTUBE_REFRESH_TOKEN — the long-lived refresh token.

GitHub stores repository secrets encrypted at rest and makes them available only to the repository's own workflow runs; they are not visible in logs, are never printed by the automation, and are never committed to the repository's files. The automation runs on GitHub-hosted runners operated under GitHub's infrastructure and privacy terms.

6. Data we store outside Google and GitHub

The only record the automation keeps of its own activity is a small ledger file (content/uploads.json) inside the private automation repository, containing for each day:

  • the content date,
  • the YouTube video ID,
  • the private video URL,
  • the video title, its privacy status, and an upload timestamp.

This ledger exists to prevent duplicate uploads and to give the owner a record of what was uploaded. It contains no OAuth tokens, no credentials and no personal data. Generated videos are stored as temporary build artifacts and are not committed to any repository.

7. This website

This site (hosted on GitHub Pages) is purely informational. It sets no cookies, loads no third-party scripts, fonts or analytics, and collects no personal information from visitors. Standard, anonymous server logs generated by GitHub's infrastructure are governed by GitHub's Privacy Statement.

8. What we do NOT do

  • We do not sell, rent or share any data with third parties.
  • We do not read or analyze your YouTube account data (history, comments, likes, subscriptions, playlists, analytics).
  • We do not use tokens or video data for advertising, profiling, or training machine-learning models.
  • We do not transfer OAuth credentials to any service other than Google's own OAuth and YouTube API endpoints.

9. Retention and deletion

  • OAuth refresh token: retained in GitHub Actions Secrets for as long as the automation is active. You can revoke access at any time — see §10 — after which the token becomes unusable. Delete the secret from GitHub afterwards (Settings → Secrets and variables → Actions).
  • Access tokens: exist only in memory during a run (about one hour) and are not stored anywhere.
  • Upload ledger: kept until you delete it or the repository. It contains no personal data; individual entries can be removed at any time.
  • Uploaded videos: remain in your YouTube account as private videos until you delete them from YouTube Studio. The automation never deletes videos (and holds no permission to do so).
  • Generated content and rendered videos: kept in the automation repository/artifacts; rendered videos are stored as GitHub Actions artifacts for 30 days.

10. Revoking access

You can revoke the automation's Google access at any time:

  1. Open your Google Account → Security → Third-party apps with account access.
  2. Select the Mindforge OAuth client and remove access. The refresh token becomes invalid immediately.
  3. Optionally delete the three YOUTUBE_* secrets from the GitHub repository.

11. Security

Credentials are limited to a single, narrowly-scoped permission, stored encrypted, and used only in short-lived server-side exchanges. The automation repository is private. No secrets are printed to logs or committed to Git. If you ever believe a credential was exposed, revoke it via §10 and generate a new one; revocation is immediate.

12. Children's privacy

This automation and website are not directed at children under 13 and do not knowingly collect any personal information from anyone, including children.

13. Changes to this policy

If the automation's data handling changes (for example, a new permission or a new data type), this policy will be updated and the effective date above revised. Material changes will be reflected on the homepage.
